# Design

The [reviewed plan](docs/collab/plans/PLAN.md) records the product model and later gates. R-001 moved the earliest end-to-end report flow into G1. The [G1 migration](db/migrations/001_report_slice.sql) defines the four runtime tables for owner-scoped reports, versions, drafts and jobs. The [G0 draft DDL](docs/collab/plans/rpt-draft.sql) is historical.

A report version stores a declarative specification. The FastAPI server validates the bearer or uses the fixed local subject, derives an internal owner key, and scopes access to that key. A patch changes one section inside a revisioned draft. Preview snapshots that draft and can compare a section or full report with an authorized output for the same saved version and fiscal period. Save appends an immutable version and advances the report head in one transaction. Generation jobs use a pinned version and target fiscal period.

The worker uses a bounded SQL transaction to claim and complete a job using row locks. Source operations use a separate read-only repeatable-read connection. A stable physical-source marker permits retrieval from the same snapshot after the quiet period. Retrieval supplies exact decimals and opaque citation locators. The model selects an evidence handle and the engine renders its value deterministically. HTML escapes untrusted fields and JSON preserves the source and change basis. Readiness markers hash metadata only. The worker carries a preset cap on sections, fiscal scopes and model calls per job.

The G1 worker can rerun a saved version for a caller-specified quarter. Automatic quarter discovery, provisional publication, correction resolution and background account wiring belong to later gates. Independent source tables and transactional, owner-scoped output are covered by the synthetic PostgreSQL tests. [R-001](docs/collab/reviews/R-001.md) · [G1 plan](docs/collab/plans/PLAN.md)
