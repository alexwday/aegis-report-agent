## Decisions

| IDs | Decision and reason |
|---|---|
| D-001, D-002 | Use Python/FastAPI/pgvector with durable Postgres jobs and typed adapters. An inline worker gives up durability, an external broker adds infrastructure, and raw table access leaks source differences. |
| D-003, D-004 | Store typed versioned pipelines with isolated previews and explicit promotion. This keeps drafts, saved versions and schedule pins independent and avoids an arbitrary execution surface. |
| D-005, D-006 | Deliver reusable retrieval and evidence before considering a global catalog. Start with private user resources, shared system templates and HTML/JSON output to limit governance and rendering work. |
| D-007, D-008 | Check physical source readiness and fingerprint relevant data before quarterly generation. Persist chat events for resume. Availability-only scheduling and a transient stream lose important state. |
| D-009 | Expose opaque citation references with stable locators rather than exposing storage internals or copying entire source files. |
| D-010, D-011 | Retain the unredacted page body locally, mark the public redactions and record the human's ring-over-A clarification. |

## Risks and issues

- RISK-001 local source shapes can diverge from live tables. Compare sanitized catalog facts and revise fixtures before enabling production adapters.
- RISK-002 peer comparison may mix incompatible fiscal periods, units or currencies. Require a declared alignment basis and explicit comparability.
- RISK-003 truncate/reload and variant overlaps may yield duplicate or stale evidence. Use content-aware revisions, anchor checks and verified version matching.
- RISK-004 retrieval and synthesis may be costly or unsupported. Filter and cap every stage and require validation before rendering.
- RISK-005 literal raw publication conflicts with the pack's hygiene requirements. The public transcript identifies each removal and the full text stays local.
